205: **Each card loads only its own layers' dense weights** (0.1.39, PR #639) with explicit split points (`--layer-split
206: 27`, not `auto`): every card used to keep a full copy (~3.4 GB for the Coder) though its stage reads only its own
207: layers, and the VRAM it frees goes to that card's expert cache (2x MI50 16 GB, Coder: 8,819 -> 10,626 experts in
208: VRAM, decode 39.2 -> 41.7 tok/s). Opt-in for now, on AMD and NVIDIA alike: `STRATA_STAGE_TRIM=1` (please report how
209: it goes).
210: A card holding more experts can change which experts run on the GPU, so the output can differ slightly from a run
211: without it.
212: 
213: **The resident RAM mode works on a split** (`--resident-experts`, the low-RAM mode). The RAM copy of the experts
214: leaves out the ones every card's cache holds, not only the first card's, and when the rest does not fit whole it keeps
215: the hottest by the expert profile over all the layers. An adaptive swap copies the evicted expert back into RAM from
216: the card that owns its layer. Before, `--resident-experts` with a split ran as `--mmap-experts`, and setup recommended
217: one card in the low-RAM mode; with an engine that has it (`RESIDENT_SPLIT_ENGINE` in setup.py), setup keeps the cards
218: together and the experts no card holds in RAM. The same copy, sized by a RAM budget (`--resident-budget-gib`, the
219: Unsloth UD-Q4_K_XL and UD-IQ4_XS configs), is kept on a split as well ([UNSLOTH_Q4.md](UNSLOTH_Q4.md)). Swift 1.5 IQ3_XXS at
220: 160K (q4_0 KV, `--prefill 4096`, `--spec 4` with the stock draft layer), RTX 4060 Ti (layers 0-19) + RTX 5080 (20-47),
221: i9-14900KF, 32 GB of RAM, Windows 11, four greedy prompts at a time, decode tok/s:

225: | 5080 alone, `--resident-experts` | 25 | 29 |

229: The split with `--mmap-experts` catches up once the OS file cache holds the experts, on a PC with nothing else
230: running; the resident copy is there from the first request and stays locked when other programs need the RAM. With
231: `--pcie-frac 0 --adapt-every 0` the split's greedy output is the same with either mode.

233: **The prompt path's loan on a split and its streamed ring (`STRATA_SPLIT_RING`).** Under a split the prompt path borrows
234: the tail slots of each card's expert cache for its buffers (they are given back after the prompt), and the resident RAM
235: copy keeps those experts too, so a borrowed expert is not read back from the model file during a prompt. How many slots
236: are borrowed depends on the prompt path's streamed ring: a split uses 96 ring slots when at least 75% of the (layer,
237: expert) pairs sit in some card's cache, and `STRATA_SPLIT_RING=N` sets N slots (`0` goes back to the pinned-share rule).
238: The ring used to be chosen after the RAM copy's regions were sized, so the regions were sized for a different ring than
239: the prompt path then used: with `STRATA_SPLIT_RING=384` it borrowed 5,396 slots and the copy kept 4,662, and the
240: other 734 were read from the model file in every chunk. The ring is now chosen first (`Prefill::set_ring_override`
