   engine" when the task is about one engine of a mapped project and the doc at the user's version is the other

   `--head-device` flag appears in the v0.2.6 flag list"): not sent, never marked. Negating a use ("do not set X",
   "without any X override", "X has no effect") does not count.                                [4]
4. The attributed -> described relabel: a table cell is read with its row's first cell (o04: "| **llama.cpp** ..."),
   bold/code marks are removed before the owner test ("PR **#29191**"), and "other-engine" is relabelled only when the
   project's own code has the name (not only docs, tests or bench notes, where other programs' flags are written down
   too: --load-mode in a llama.cpp run's README, --prefetch in a Metal test comment).          [2]
5. With no code read at all (o05): any mark left says "unverified for X: its code was not read", and the section
   says so too.                                                                                [3]
6. other-version / not-found with no hit at the user's version, where the only sources naming it are the user's
   own attached files: kind "own-build" ("not in the code at your version; only your own files name it (your own
   build's setting?)") instead of "another version". The mark count is unchanged.             [6]
7. Engine split for "this-version" names: exactly one engine's code reads the name at the user's version (engine
   map; no hit in shared/unmapped code, nor of the name's tail elsewhere), and sentences set it for the other engine
   (that engine's markers in the name's clause, plus a set/enable/config cue) -> marked "a setting of another engine
   of the same project" at those sentences, one per section.                                 [7]
