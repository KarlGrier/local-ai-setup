## The hand ports: what changed and why

**13 - think-fence (frontend.py).**
- v0.2.9's 209dcadb3 (#4702 / #4703) gave the parser's tracking five fields (`fence, line, ticks, _prev_blank,
  _indented`) and the helpers `_snap()`, `_restore()` and `_reset_track()`. `line` is now a property over line parts.
- Our hold uses them. `fhold_state` is the 5-field snapshot (initial `("", "", 0, False, False)`), `_fenced_at` and
  `_hold_more` go through `_snap` / `_restore`, and the unclosed-fence fallback calls `_reset_track()`.
- So a held fence now closes the #4702 way: only on a line of the same character, at least as long as the opener.
- `finish()`: our fallback runs first, then upstream's new #4701 branch (`_final`). While a hold is open the parser is in
  "reasoning", where #4701's branch does nothing. Our fallback switches it to "content", so #4701 can then settle a tool
  call that the released answer left held. Our test `test_an_unclosed_fence_falls_back_to_the_last_tag` needs this order.

**17 - continuation fix + #652 (serve loop, generate.cpp).**
- `lim` (tcap) is declared after upstream's HIP-only `stop_bound` switch. The loop head, the coupled-history line (now
  upstream's `pen_gen0` window) and the draft call (now `!draft_on || ... || (req_df2 ? DFlash2 : mtp.draft_long(...))`)
  all run to `lim`.
- The `emit` block computes, before `ver.commit(emit, err)`, what the window hands out. That commit keeps upstream's new
  `exit_if_gpu_fatal(err)`.
- `consumed` takes the `emit` tokens. Upstream's DFlash2 `note_rows` / `--draft auto` upkeep follows, left at `a + 1`.
- DFlash2's end-of-request update (`df2_end_update`) also ends at `lim`, as the draft call does.
- The pipeline path is still made serial under a tcap (`pl_serial`).

**19 - fork scratch (verify.cpp).**
- The head's final-mixer read is now a column-chunk loop: `h0`, `HT <= kFusedGrMaxT`, for --lookup-max-t windows.
- Both reads the fork can reach (`fuse_head_gr` and the HEAD_MIX_MULTI mixer) pass `grfk_` in every chunk and keep
  upstream's `q8_head` return. The chunks run one after another on one stream, and the fork's counters reset themselves.
- The STRATA_HC_Q8 head read keeps `xn_ + h0 * HC * N`, because its q8 branch returns before the fork (as on v0.2.8).
- `grfk_` is carved after `xn_` (back to T x HC x N), and the arena is still zeroed after carving (verify.cpp:1131).

**24 - SPEC_EXACT (generate.cpp, serve and CLI loops).**
- The lookup check is upstream's new `(probabilistic || !draft_on || sbuf[0] == ...)` with
  `probabilistic = use_mtp && !req_df2 && mtp.prob()`.
- It compares with the drafter's raw argmax `ess_top(0)` only on an MTP round (`use_mtp && !req_df2 && mtp.ess()`), and
  with `drafts[0]` otherwise.
- `set_spec_window` comes after upstream's new `mtp_q_applies(...)` / `set_spec_q` line and is off on a DFlash2 round.
- Merged without conflicts and checked:
  - our exact branch in `Verifier::run` still comes before SPEC_PROB's `T <= kVerifyMaxT` branch, with no row limit
    (`sample_tokens_spec` takes 64 rows, scratch max(T, 16));
  - `draft_long` ends in an ordinary `draft()` round, so the exact draw and the q lists are made as before.

**25 / 26 / 27 - cost gate, past its steps, DRAFT_CUM (generate.cpp).**
- v0.2.10 moved both loops' window-size if/else into `strata::spec::choose_window` (spec/window_rule.hpp). Upstream's

## Judgement calls (v0.2.10's code forced a choice)

1. **13:** the hold starts only inside a ``` / ~~~ fence, as on v0.2.8, not in a #4703 indented code block. Upstream
   tracks those for tool-call openers only. A `</think>` in an indented block of the reasoning still ends the thinking.
2. **13:** in `finish()` our hold is released before upstream's #4701 branch (see above).
3. **17:** on CUDA ours is the only stop bound, because upstream's `serve_stop_bound` (#4677) is `#if STRATA_USE_HIP`. A HIP
   build would run both. That is harmless (emit <= a + 1), but pick one there.
4. **17:** DFlash2's `note_rows` / `context_async` stay at `a + 1` (DFlash2 only). `df2_end_update` now ends at `lim` like
   the draft call (DFlash2 only).
5. **19:** every head chunk reuses the same `grfk_` region (group 0's), sequentially.
6. **24:** exact sampling is off on a DFlash2 round (`req_df2` / `spec_uses_df2`). Those candidates are not draws from the
   MTP's q, so the exact-match rule judges them (sample-and-match, exact per seed).
7. **25-27:** I overrode T after `choose_window` instead of adding fields to upstream's `WindowRuleIn`. That gives fewer
   upstream lines to conflict with at the next port.
8. **25-27:** the gate and DRAFT_CUM apply to MTP rounds only. A DFlash2 round keeps upstream's min_p / draft_conf rule.
   On v0.2.8 our gate also sized DFlash2 rounds, which was the upstream bug that `window_rule.hpp` fixed.
9. **27:** DRAFT_CUM does not observe a DFlash2 round, as it already skipped lookup windows (those drafts are not the MTP's).
10. With `"drafting": "mtp"` none of the DFlash2 branches (4, 6, 8, 9) is ever on our path.
11. **Upstream overlaps, kept (none is byte-for-byte redundant):**
    - #652: `serve_stop_bound`, HIP only, without the tcap.
    - Think-fence: #4702 / #4703 are complementary, and #2794 is still open.
    - GR_FORK beside v3 + GR_V3_PF / GR_R2: a speed question, not a merge.
    - Cost gate / DRAFT_CUM beside STRATA_SPEC_COST and `choose_window`: no upstream copy of our rules.
    - SPEC_EXACT beside SPEC_PROB: spec_prob.hpp is unchanged.
    - SIDE_MIXER and QSA_SPLIT_ATTN are upstream's own switches now; only our guards for them remain.

**Seen and not changed (it was the same on v0.2.8):** `set_spec_window` passes `T - 1` as the MTP-row count, and that
count includes `--lookup-chain`'s tail rows. Those rows would read q lists the MTP did not write in that round; upstream's
