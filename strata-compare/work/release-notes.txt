===== v0.1.9 2026-09-27T14:59:18Z ['strata-windows-x64.zip']
**No more stalls on a full GPU, access from other devices on your network, and an experimental option.**

- **Fixed: requests could stall forever at large contexts.** The engine sized its expert cache before loading the output head (~0.5 GB), so the head used up the VRAM it meant to keep free. IQ3_S at 128K ended with 30 MiB free, Windows started paging GPU memory, and a request could hang at "reading the prompt" with the GPU at "100%" but low power. The head now loads first. The same 700 MiB reserve really stays free (about 500 MiB with everything loaded), and decode was not slower in our tests (Q2_0 at 32K: 78-79 tok/s vs 71.7 before). If free VRAM still ends below 256 MiB, the start-up line now says which `--vram-reserve-mib` to add.
- **Use it from your phone or another PC (#26, thanks @XeonG).** `START-HERE.bat --setup --host 0.0.0.0 --api-key <secret>` (or `"host": "0.0.0.0"` and `"api_key"` in `strata-<model>.json`). The server window prints this PC's network address, warns if there is no API key, and on Windows shows how to allow it through the firewall.
- **`--fit-max-tokens` (#24, thanks @pjgmobile).** Optional: a request whose `max_tokens` would run past the context gets a shorter answer instead of a 400 error (for agents that always ask for their full output cap). Off by default; turn it on with `"fit_max_tokens": true` in `strata-<model>.json`. A prompt that already fills the context is still refused.

When it is on, the web app's Sampling drawer (or `"experimental_speed_projection": false` in a request) switches it off per chat. ===== v0.1.7 2026-09-27T08:32:27Z ['strata-windows-x64.zip']
**Faster code edits (prompt lookup), temperature and sampling that actually work, and three fixes.**

- **Prompt lookup, on by default.** When the reply repeats text from the conversation (an agent rewriting a file, quoting code or a document), the engine now drafts up to 5 tokens from the earlier copy. It only does this where it has measured that it pays: code edits are 6-11% faster (e.g. 101 -> 112 tokens/s), and other text is unchanged. Drafts are checked by the model like the MTP's, so the output is the same. Turn it off with `--suffix-draft 0` in your config's `args`.
- **Per-request sampling (#19, thanks @j-luwierski).** `temperature`, `top_p`, `top_k`, `min_p`, `seed`, `repetition_penalty`, `frequency_penalty` and `presence_penalty` from the request are honored. Before this, every request decoded greedily whatever the client sent. You can set defaults in an optional `sampling` block in your `strata-*.json`. Greedy requests (no temperature, or 0) are exactly as before, at the same speed. The same seed gives the same text. Image requests still decode greedily.
- **Replies no longer stop at 1,024 tokens (#18, thanks @coolio986; fixes #17).** A missing, `0` or `-1` `max_tokens` now means "the rest of the context".
- **Setup on a short path (#20).** Installing to a folder like `G:\Strata` crashed step 6 with `IndexError: 1`; fixed.
- **Setup on too little RAM (#20).** Setup now says at step 1 when the PC has less RAM than the smallest model needs. All of the model's experts live in RAM (34-50 GB); the GPU holds a copy of the most-used ones, so a bigger GPU does not lower the RAM needed.

===== v0.1.5 2026-09-27T06:39:59Z ['strata-windows-x64.zip']
**KV streaming: faster long contexts.**

At 64K context and more, the KV cache (the model's memory of the conversation) now lives in RAM. Only the part the attention is actually reading stays on the GPU. The VRAM this frees holds more experts, so decoding is faster:

- **Q2_0 at 262K:** 50.9 -> 62.6 tokens/s. Experts in VRAM go from 1,589 to 3,872.
- **Q2_0 at 128K:** about +6%.
- **IQ3_S at 128K:** about +1% (its experts are bigger, so the freed VRAM holds fewer of them).

Measured on an RTX 5070 12 GB, Ryzen 5 7600, 64 GB.

- **It doesn't change what the model computes.** The attention reads exactly the same values; only where the KV lives changes. With the same experts on the GPU, the output is identical token for token. All needle tests pass (1K to 262K).
- **It costs RAM:** ~13.7 KB per context token, so 1.7 GB at 128K and 3.4 GB at 262K. Setup only turns it on when that fits next to the model.
- **Prompt reading:** about 1% slower at 262K.

**Turning it on:** new installs get it automatically at 64K+ context. For an existing install, run `START-HERE.bat --setup` once and pick the same model and context; nothing is downloaded again. You can also add `--kv-resident 32768` to the `args` in your `strata-*.json`.

Also in this engine: an opt-in suffix drafter (`--suffix-draft`). It proposes drafts when the reply repeats text from the context. It's off by default.

**Updating:** get the latest files (`git pull` or download the repo again), then run `START-HERE.bat` with the model window closed. It updates the engine by itself before starting. On Linux, `./setup.sh` builds the engine from source as before.
